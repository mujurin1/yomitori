# コードコメント ルール

コードから読めない制約だけを書け。判定は 1 つ: そのコメントを消したら、次にこのコードを変更する者が壊すか。No なら書くな

## 書く

- なぜこの形か。素直な書き方に直すと何が壊れるか
- 変えると壊れる前提・順序・外部との契約
- 1〜2 文で書く。長くなるなら、lint / test / 型で止められないかを先に考える（読まれない場所で踏まれる制約は、コメントでは守れない）

## 書くな

- コードの言い換え（何をしているか）。名前と型で表す
- 経緯・差分（「#439 で〜に変わった」「以前は〜だった」）。経緯は commit の担当。経緯しか情報が無いコメントは丸ごと書かない
- 関数名・引数名を繰り返すだけの doc コメント（`///`）、区切りだけの見出しコメント
- 中身の代わりに設計書・リポジトリ外の文書を指すこと。要る中身は数行になってもその場に書く（参照先が消えたり手元に無かったりすると、ポインタだけが残って腐る）

## 状態

- 現在のコードの姿と制約だけを宣言的に書く。コードを変えたら、同じ変更でコメントも直すか消す
