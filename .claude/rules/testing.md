# テストルール

- テストは `src/logic/` の各モジュールの末尾の `#[cfg(test)] mod tests` に置き、`cargo test` で流す。対象は画面に依存しないロジック（`src/logic/`）。画面・Win32・OCR・HTTP に触れる部分は logic に判定を切り出してからテストする
- テスト名（`#[test]` の関数名）は日本語で、仕様を述べる文にする。ASCII の部分は小文字にする（大文字は `non_snake_case` の警告になる）
- テストから外部サービス（翻訳の HTTP 等）へ実リクエストを投げるな。`HttpGet` 等の trait で差し替える

## 何をテストするか

- 書くのは specification test のみ:「これが正しい」「これは絶対起きない」を行動（input → output）で固定する。仕様を変えない限り壊れない
- characterization test（現状実装の再現）は書かない。実装変更で壊れる負債になり、silent regression も防がない
- 同じ形のテストを値ごとに並べるな。ケースの表を 1 つの関数の中で回し、assert の message にケースを出せ
- ファイル操作に依存するロジックは、操作を差し替え可能にしてテストする（実ファイルに触れるなら一時ディレクトリで）

## 検証の質

- バグ修正・防御機構には負の対照を付ける: 修正を無効化して問題が再現し、戻すと消えることまで確認して「効いた」と言う
- 不変条件を守るテストは、実装をわざと壊して落ちることを確認する（落ちないテストは何も守っていない）。自明な入出力のテストにまでは求めない
- 実機（ホットキー・オーバーレイ・OCR）でしか確かめられない挙動は、確かめた事・確かめていない事を分けて報告する

## やらないこと

- スナップショットテストは使わない
- カバレッジの数値目標は設けない
